Add a `[resources.data_dir]` section to `manifest.toml` under `[resources]`, placed after `[resources.install_dir]`:

```toml
    [resources.data_dir]
```

Rationale (from 02-RESEARCH.md Pitfall 1): both `conf/librechat.service` and `conf/meilisearch.service` use `__DATA_DIR__` (meilisearch `--db-path __DATA_DIR__/meilisearch`, `ReadWritePaths=__DATA_DIR__`), but the data_dir resource was never declared, so the YNH core may render an empty `__DATA_DIR__` and never create/chown the directory. Declaring it is idempotent even if the core would happen to inject it anyway — one line, eliminates the risk. Do NOT add subdirectory config; the helper creates `$data_dir/meilisearch` paths at runtime if needed (meilisearch creates its own db-path dir).
  </action>

<task type="auto">
  <name>task 2: Implement scripts/remove (Wekan pattern, MongoDB-namespaced-safe)</name>
  <files>scripts/remove</files>
  <action>
Replace the stub in `scripts/remove` with the full remove script, following 02-RESEARCH.md Pattern 1 exactly. Order matters:

1. Keep `source /usr/share/yunohost/helpers` and `ynh_abort_if_errors`.
2. **Stop services first** so nothing writes during removal:
   `ynh_systemctl --service=$app --action=stop` and `ynh_systemctl --service=meilisearch --action=stop` (each guarded with `|| true` — they may already be down).
3. **Deregister from YNH service monitoring** (only if registered, per Wekan):
   `ynh_hide_warnings yunohost service status $app >/dev/null && yunohost service remove $app` — same for `meilisearch`.
   Use if-guards so remove-after-failed-install doesn't error.
4. **Remove systemd units** (also stops/disables):
   `ynh_config_remove_systemd` (defaults to $app) and `ynh_config_remove_systemd --service=meilisearch`.
5. **Remove nginx config:** `ynh_config_remove_nginx`.
6. **Read settings explicitly** (Pitfall 5 — `$db_user` is not stored as a setting, only `db_name`):
   `db_name=$(ynh_app_setting_get --key=db_name)`, sanity-check non-empty (`[ -n "$db_name" ] || ynh_die "Cannot find db_name app setting"`), then `db_user=$db_name`.
7. **Remove ONLY the namespaced DB:** `ynh_mongo_remove_db --db_user=$db_user --db_name=$db_name`.
   Do NOT write a comment calling `ynh_remove_mongo`; add a comment marker `# NEVER call ynh_remove_mongo here — it removes the global MongoDB service integration (RMV-02/RMV-05)`.
8. **Remove Node ref-counted:** `ynh_nodejs_remove` (helper only deletes Node 24 if no other YNH app uses it — never `rm -rf` the nodejs dir).
9. **Remove meilisearch binary** (our package owns /usr/bin/meilisearch, single instance):
   `if [ -x /usr/bin/meilisearch ]; then rm -f /usr/bin/meilisearch; fi` (Pitfall 6 — tolerant if missing).
10. Do NOT `rm` `$install_dir` or `$data_dir` — the YunoHost core removes those after the script returns (`--purge` handles data_dir). Note this in a comment.
11. Final `ynh_script_progression "Removal of $app completed"`.
  </action>
