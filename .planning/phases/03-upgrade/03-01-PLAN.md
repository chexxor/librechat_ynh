    2. **librechat.env merge** (env path: `$install_dir/librechat.env`):
       - Generate FRESH template to `$install_dir/librechat.env.new` via `ynh_config_add --template="librechat.env" --destination="$install_dir/librechat.env.new"` (all template vars in bash scope).
       - If existing `$install_dir/librechat.env` exists AND is non-empty: for each `KEY=...` line in the OLD file whose KEY is NOT present at file start-of-line in the NEW file, append the old line to the new file (preserves user-added keys verbatim). Managed keys always take the freshly regenerated value (fixes stale port/URI).
       - `mv` new file over old, `chown $app:$app`, `chmod 600`.
       - If no existing file: just `mv` the generated one into place with same perms.
       - Guard: if generation failed (new file missing), `ynh_die` — never silently replace configs with nothing.
    3. **librechat.yaml merge** (yaml path: `$install_dir/librechat.yaml`):
       - If existing file exists and is non-empty: PRESERVE it. Then, for the template's commented example sections, append only commented template top-level sections whose key name does not appear as an active (non-comment) top-level key in the user's yaml. Simplest robust way: regenerate template to `$install_dir/librechat.yaml.new`, diff top-level active keys (`grep -v '^\s*#' yaml | grep -v '^\s*$' | sed 's/^\([^# ]\S*\):.*/\1/'` style) between new and user file; append `.new` lines for absent keys as comments; rm the `.new`; never modify existing user lines.
       - If missing: `ynh_config_add` full template in place.
    4. `chown $app:$app` both final files; `chmod 600` env, `chmod 644` yaml.
    5. Echo/ynh_print_info what was merged for observability.

    Do NOT use `ynh_store_file_checksum`-style nor backup_file diff helpers — explicit merge logic per research doc. Do NOT re-run librechat_generate_secrets here (would rotate secrets and invalidate sessions — upgrade never regenerates).
