   - write `/etc/apt/sources.list.d/zabbly-incus-lts-7.0.sources` with `URIs: https://pkgs.zabbly.com/incus/lts-7.0`, `Suites: $(. /etc/os-release && echo ${VERSION_CODENAME})`, `Components: main`, `Architectures: $(dpkg --print-architecture)`, `Signed-By: /etc/apt/keyrings/zabbly.asc`

4. **Group membership:** `usermod -aG incus-admin "$TARGET_USER"` and a printed reminder that this applies at next login (`newgrp incus-admin` or re-SSH).

Comment why: `dir` storage has no fast CoW snapshots, which package_check relies on.
6. **YunoHost image remote:** idempotently `incus remote add yunohost https://repo.yunohost.org/incus --protocol simplestreams --public` (guarded by `incus remote list -f json | jq -e '.yunohost'`).

8. Document `BTRFS_DISK` as an overridable env var; state that `incus admin init` must have created the `incusbr0` bridge (script should print a note if `ip a | grep incusbr0` is empty, without hard-failing).

Every mutation must be guarded so a second run is a safe no-op/repair. Keep the file LF-only (the repo's `.gitattributes` pins `*.sh text eol=lf`).

Avoid: `incus admin init --minimal` as the storage path (dir-backed, defeats snapshots); installing `incus` without the Zabbly repo; hard dependencies on a specific disk name without an override; CRLF line endings.
